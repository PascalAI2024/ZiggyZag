## Real defects, fixed

### 1. AgentD watchdog deadlock (`apps/agentd/src/tools.zig`)

**What was wrong.** `commandJsonAlloc` (used by `rg.search` and `git.diff`) ran a watchdog thread that called `std.Io.sleep(timeout_ns)` unconditionally. Nothing could cancel that sleep, so:

1. The main thread reaped the child as soon as it exited.
2. The main thread then called `watchdog_thread.join()` — which blocked for the full timeout because the watchdog was still sleeping.
3. The watchdog eventually woke up, stored `fired = true` unconditionally, and tried to kill the (already dead) child.
4. The main thread checked `fired`, found it true, and returned `error.ToolTimedOut`.

Net result: **every successful `rg.search` and `git.diff` call waited 30 seconds and then returned a timeout error.** The existing test suite did not catch this because no test exercised the `commandJsonAlloc` success path; the `shouldKill` helper test is dead code as far as the integration goes.

**Fix.** Replaced the single big sleep with a 100 ms polling loop. Added a `main_done: std.atomic.Value(bool)` field to the `Watchdog` struct. The main thread sets `main_done = true` after `child.wait` returns; the watchdog notices it on the next tick and exits without firing. Worst-case latency after successful command completion is now 100 ms instead of 30 seconds.

**Test added.** None this pass — integration test for the real spawn path requires a cross-platform fast command. Tracked as a follow-up.

### 2. `theme` directive silently ignored in `~/.ziggyzagrc` (`apps/shell/src/main.zig`)

**What was wrong.** The new `theme` builtin (shipped in this wave) was reachable as an interactive command but the startup config loader (`applyConfigLine`) did not recognise it, so `theme tokyo-night` in a user's `.ziggyzagrc` had no effect. Same omission in `isConfigDirective`.

**Fix.** Added `theme` to the dispatcher and to `isConfigDirective`. Now consistent with how `prompt` is handled.

**Test added.** Extended the existing `"config directives and names"` test to assert `isConfigDirective("theme")`.

### 3. JSON encoder produced invalid output for sub-0x20 control bytes (`apps/shell/src/main.zig`)

**What was wrong.** The shell's `appendJsonString` escaped only `\n`, `\r`, `\t` plus the obvious `"` and `\`. Every other byte below 0x20 — NUL, BEL (0x07), VT (0x0B), etc. — was emitted raw. RFC 8259 requires all control characters be escaped, and POSIX filenames or env values can legally contain them, so any `path --json`, `env --json`, `vars --json`, or `doctor --json` invocation that touched such a value produced malformed JSON.

The AgentD copy of the same function (`apps/agentd/src/protocol.zig`) was already correct — it short-formed `\b`/`\f` and `\u00XX`-escaped everything else under 0x20.

**Fix.** Brought the shell version up to RFC 8259 conformance and into agreement with AgentD: short forms for the five common escapes plus `\u00XX` for all remaining sub-0x20 bytes.

**Test added.** `"JSON encoder escapes all sub-0x20 control bytes"` — pins the round-trip for NUL/SOH/BEL/VT/US plus the common escapes and the literal `"`/`\` handling.

### 4. History metadata never loaded on startup (`apps/shell/src/main.zig`)

**What was wrong.** The shell wrote a `ZIGGYZAG_HISTORY_DB` TSV at process exit (timestamps, exit codes, durations, cwd, command) and recorded into `history_meta` for each command, but never read the file back at startup. Result: every session started with an empty `history_meta`, so `history --stats` / `--slow` / `--cwd` / `--failed` could only see the current session. The persistence existed but was effectively one-way.

**Fix.** Added `readHistoryMetaFile` paired with the existing `writeHistoryMetaFile`. Added a paired `unescapeTsvFieldAlloc` helper (companion to `appendTsvField`). Wired the load call into `run()` after `readHistoryFile`. Unknown `\\X` sequences in the TSV fall back to literal `X` so a hand-edited file degrades gracefully.

**Test added.** `"TSV field escape and unescape round-trip"` — pins the encoded form (no raw tabs or newlines) and the round-trip identity across nine representative inputs.

### 5. `dir_index` mutated before `chdir` succeeded (`apps/shell/src/main.zig`)

**What was wrong.** `backCommand`, `forwardCommand`, and `jumpCommand` all set `self.dir_index = target` *before* calling `goToDirectoryIndex`, which then called `std.process.setCurrentPath`. If chdir failed (directory removed since it was last visited, permissions changed, etc.), `dir_index` was left pointing at the failed target. Subsequent `back`/`forward`/`pwd` operations used the wrong slot.

**Fix.** `goToDirectoryIndex` now takes the desired index as a parameter and updates `self.dir_index` *only after* `setCurrentPath` succeeds. The three callers were updated to pass the target rather than pre-mutating state.

**Test added.** None this pass — the natural test is "rm -rf a directory then `back` to it"; setting that up in a unit test is more harness than fix-value warrants. Worth adding to an integration smoke later.

## Real defects, deferred

### 6. `closeActivePane` can null-dereference on last-pane close (`apps/desktop/src/windows_app.zig`)

`activePane()` does an unchecked `.?` on `self.panes[self.active_pane]`. There is a guard at line 1346 (`if (self.paneCount() <= 1) return;`) that prevents the only path that would obviously trigger this in practice, but the invariant "active_pane indexes a live pane" is not enforced by the type system. A defensive `activePane() ?*Pane` signature change is the right fix; it requires updating ~20 call sites. Tracked for a dedicated commit so the diff stays reviewable.

### 7. `bestEffortId` returns quoted slices for string JSON IDs (`apps/agentd/src/protocol.zig`)

For requests like `{"id":"abc","method":"…"}`, the extracted `request.id` value carries the surrounding quotes through to the response envelope. Existing tests (`lines 344, 360`) pin the current broken behavior. Fixing it requires either changing the contract (`id` is JSON-raw) or normalising at parse time (`id` is unquoted string). A design call, not a one-line patch.

### 8. Stderr drain leak if stdout `allocRemaining` errors (`apps/agentd/src/main.zig`)

If the stdout drain fails with OOM mid-command, the stderr drain thread keeps reading from the child's stderr after the parent function frame returns. Niche but real. Fix is straightforward — `errdefer stderr_thread.join();` before the failing call — but it deserves a careful look at the surrounding cleanup ordering rather than a one-line patch.

## Candidates that turned out NOT to be bugs

Documenting these matters: they're places future audits will pattern-match and re-report.

### 9. "Disowned `Child` becomes a POSIX zombie"

Background jobs spawned by `spawnBackgroundProcess` use the default `std.process.spawn` config — no pipe overrides — so stdin/stdout/stderr are inherited from the shell. The `std.process.Child` struct in this code path has no owned pipe handles to close on disown. The PID is intentionally not waited on (that's the contract of disown). Not a leak.

### 10. "Pipeline temp-input file leak on `PipelineOutputTooLarge`"

The relevant `defer` evaluates the captured `temp_input` variable at function-return time, not at definition time. So if `temp_input` is set to a valid `PipelineInputFile` after the defer is registered, the defer correctly closes/deletes/frees on the error return. No leak.

### 11. "History-scroll math underflow at edges"

The scroll start computation is guarded: `if (history_len > height + scroll_offset) history_len - height - scroll_offset else 0;`. All operands are `usize`. Under the true branch the subtraction is safe. Pathological `height + scroll_offset` overflow would require values pushing `usize::MAX`, which the surrounding code makes structurally impossible. Not a bug.

### 12. "`requestUiRefresh` PostMessageW to a null/destroyed hwnd"

`self.hwnd` is set once in `run()` and never cleared. When the window is destroyed, the stored pointer becomes stale; `PostMessageW` to a stale HWND is documented Win32 behavior — returns 0, no crash, no UAF. No null-deref path exists. Not a bug (under the current shutdown design).

## Round-2 addendum — 2026-05-17 (later)

A second sub-agent pass was dispatched to verify+sketch fixes for the three "deferred-real" bugs (5 — closeActivePane, 11 — bestEffortId, 12 — stderr drain). All three were re-examined against the actual source. **All three were downgraded to NOT REAL** on closer reading:

### Bug 5 re-verified as NOT REAL

The crash path requires `closeActivePane` to leave `active_pane` pointing at a null slot. There's already a guard at line 1346 (`if (self.paneCount() <= 1) return;`) that prevents the only path that would obviously trigger it. The agent's "concurrent close" concern would require pane manipulation from a non-UI thread; in the current code, panes are only mutated by the UI thread (via `WM_CLOSE`, palette actions, keybindings), and reader threads acquire `app.mutex` only to read grids. No concurrent close path exists in the codebase as-is. Bug is potential-future-debt, not present-day defect.

### Bug 11 re-verified as NOT REAL

The auditor (and the verifier agent) both confused themselves about JSON representation. For input `{"id":"abc","method":"foo"}`, `jsonRawValue("id")` returns the 5-byte slice `"abc"` (including the surrounding quotes — these are *JSON syntax*, not extra characters). `bestEffortId` returns that slice. `writeOkEnvelope` writes it via `appendSlice`, not `appendJsonString`, so the output is `"id":"abc"` — valid JSON in which `id` is the string `"abc"`. **The round-trip is correct.** Existing tests at lines 344 and 360 are *also* correct: they pin the parsed slice-form, which includes the quotes by design. No fix needed.

### Bug 12 re-verified as NOT REAL

The agent missed that Zig's `allocRemaining` returns an error union (`![]u8`) and assigning it to a variable does NOT throw — the call at line 349 stores the error union, and line 353 (`stderr_thread.join();`) runs unconditionally before the error is unwrapped at line 355. All return paths in this function (lines 357, 360, 361, 364) execute *after* the join. The comment at line 351–352 is accurate. No leak path exists.

## Process note

Two-round audit using parallel `Explore` sub-agents produced 12 candidate findings. **5 were real, 7 were not.** Agents are excellent at *surfacing* candidate defects, unreliable at fully understanding deferred evaluation, Zig 0.16 std-library semantics (especially error-union assignment), or struct lifecycles they only see in isolation. The right discipline is: agents triage; the orchestrator verifies against source before applying any patch. Round 1 underestimated false-alarm rate (claimed 3 of 12 not real); round 2 raised that to 7 of 12. Treat agent reports as triage input, not as patches.
