A shell, a terminal, and an agent — in one weekend's worth of Zig.

ZiggyZag is a readable Zig shell, a native terminal host for Windows and macOS, and a local AI sidecar that share themes, events, and approval semantics. No accounts. No JavaScript. No nonsense.

Windows and macOS — native desktop hosts. Windows: Win32 + ConPTY with split panes, palette, AgentD panel (verified 2026-05-17). macOS: native Cocoa + CoreText window with command palette, search, quick select, theme cycling, AgentD universal input (verified 2026-06-10). Linux gets the shell + launcher; native window in next wave.

ARCHITECTURE

One workspace, four binaries, one product

The shell does parsing and execution. The desktop owns the window. The agent suggests and asks. Each piece is small enough to read in a focused sitting.

$

ziggyzag

The shell itself. REPL, parser, expansion, redirection, completion, history with metadata, background jobs, five prompt themes. About 6,600 lines.

▣

ziggyzag-desktop

Native desktop hosts for Windows (Win32 + ConPTY) and macOS (Cocoa + CoreText). Split panes, command palette, search, quick select, theme cycling, AgentD universal input, mouse-wheel scrollback, alternate screen, 256-color/RGB SGR, bracketed paste.

◆

ziggyzag-agentd

JSON-lines AI sidecar. Approval-aware for every mutation. Sandboxed reads with realpath containment. Ollama and OpenAI-compatible providers.

▸

ziggyzag-launcher

The cross-platform entry point used by release zips. POSIX hosts get the native PTY relay, with script(1) and direct stdio as fallbacks.

FEATURE TOUR

What it does, in pictures

Four surfaces that distinguish ZiggyZag from "yet another terminal." Each is built and shipping — the Windows and macOS native hosts are alpha, Linux gets the shell + launcher with a native window in the next wave.

FEATURE / 01

Split panes with real PTYs

Each pane runs its own shell process with its own cwd, scrollback, and status line. Theme cycling propagates to every pane. The status bar surfaces the active pane's git and project context.

  • PTY-backed vertical & horizontal splits
  • Per-pane scrollback ring, independent Ctrl+C
  • Pane count and orientation persisted to desktop.conf
  • Tabs land in Wave 5 (spec at sessions.md)
Ctrl+Shift+D Ctrl+Shift+E Ctrl+Shift+N Ctrl+Shift+W
FEATURE / 02

Command palette, fuzzy-ranked

Hit a chord, type three letters, get the action. Every desktop command (themes, splits, search, AgentD, settings reload, restart shell, copy cwd) is reachable without a mouse and without memorising menus.

  • Fuzzy match across action name, keybinding, recent invocations
  • Frecency-ranked results so what you used last comes first
  • Same palette surface AgentD uses for tool invocation
  • Inspired by Warp's universal input but local-first

FEATURE / 03

Five prompt themes, one toggle

From the canonical $ to a full developer dashboard with cwd, git ahead/behind, staged/changed counts, project type, last exit, command duration, and background-job count. Switch live with one command. Slash shortcuts work too.

FEATURE / 04

Approval-first AgentD

AgentD never types into the terminal on its own. Every mutating action — write into the PTY, run a build, modify a file — surfaces an approval card with the exact bytes. You hit Approve or Dismiss. Read-only tools run immediately.

  • JSON-lines protocol over stdio — no embedded webview
  • Six tools, each declaring its approval policy as data
  • Bounded reads, redacted output, realpath sandbox
  • Ollama and OpenAI-compatible providers, local-first
Ctrl+Shift+A

AGENT SIDECAR

An agent that asks before it acts

ziggyzag-agentd is a slim JSON-lines process. Every tool declares its approval policy as data — none for read-only, ask for terminal/build writes, host for actions the desktop performs on AgentD's behalf. The host UI enforces the policy. The agent process never executes a mutating action itself.

ToolApprovalWhat it doesBounds & safety
project.infononeReport workspace path and the ZiggyZag binaries it can see.Metadata only — no file contents read.
file.readnoneRead a bounded UTF-8 file from inside the workspace.64 KB cap, three-layer path sandbox: lexical filter, lstat walk, realpath containment. Output redacted for secrets.
rg.searchnoneRun ripgrep for a query inside the workspace.96 KB stdout / 24 KB stderr cap, 30 s wall-clock timeout, query bounded to 1 KB and NUL-rejected.
git.diffnoneReturn git diff -- in the current repo.Same caps as rg.search; redactor scrubs Authorization headers, Slack/GitHub/AWS tokens, PEM blocks.
zig.buildaskBuild or test the project. Surfaces approval card; never runs in AgentD itself.Host action — desktop spawns zig build after explicit approval. AgentD returns a structured intent payload only.
terminal.writeaskInsert text into the active PTY. Preview shown before approval.16 KB cap on input, NUL-rejected. Preview clipped to 512 bytes for the UI. Desktop performs the write only on Approve.

Provider connections live entirely on your machine. AgentD speaks to local Ollama by default (no network egress beyond the loopback to http://127.0.0.1:11434) and to OpenAI-compatible endpoints when configured. Full protocol at agentd-protocol.md. Security policy at SECURITY.md.

ZiggyZag is not trying to replace Ghostty, WezTerm, or Warp. WAVES, NOT DATES

Shipping in waves

Each wave has explicit entry gates, rollback criteria, and a friend-tester cohort that grows with each release. A wave is reached when every gate is green, not when a calendar says so.

wave 1

Dogfood

Pascal uses ZiggyZag as his daily terminal on Windows. Bugs filed, fixed, repeated.

wave 2

Unified theme

Theme protocol v1+v2 (OSC 7777 live updates), brand kit, landing page, ops infra, doc reorg, ConPTY bridge fixes. Tagged v0.1.0-alpha.3.

wave 3

Cross-platform

macOS native window shipped — Cocoa + CoreText with full overlay system, theme cycling, AgentD universal input. Linux native window + friend cohort 1 next.

wave 4

wave 5

Tab strip + session restore, keybinding config, theme/prompt sync polish. Public beta.

All gates green on three OSes. Signed releases. Five friend testers at 2+ weeks each.

FOR WHOM

This is for you if…

ZiggyZag isn’t trying to be everyone’s terminal. It’s aimed at a specific kind of user.

…you’re learning Zig

About 18,000 lines is small enough to step through and big enough to teach real concerns — memory ownership, process spawning, terminal escape parsing, PTY lifecycle, JSON-lines protocols.

…you want to learn how shells work

Every builtin is a tiny module. Parsing, expansion, redirection, completion, jobs are all visible in one file you can read in a sitting. The architecture doc maps it.

…you want a local-first terminal AI

AgentD speaks JSON-lines, runs on your machine, asks before mutating, and never phones home unless you wire it to a provider you control.

…you’re building a portfolio

The whole project is MIT-licensed, well-documented, and small enough to fork as a learning base. The brand kit, theme protocol, and audit framework are all reusable.

WHY THIS EXISTS

Small enough to read, complete enough to use

Most shells are either mature production tools carrying decades of compatibility code, or tiny demos that stop after echo. Most terminals are walls of C or large Rust projects with their own ecosystems. There is a middle band — small enough to read in a focused sitting, complete enough to demonstrate the hard parts, written in a language where memory ownership, process spawning, and terminal behaviour stay visible.

ZiggyZag is that band. It started as a finished CodeCrafters “Build Your Own Shell” challenge, kept growing because every new feature taught a shell concept, and is now an open-source learning lab aiming for daily-driver respectability.

Start at Quick Start. End at Masterplan. Or open the repo and read apps/shell/src/main.zig.
